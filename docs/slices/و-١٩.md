# و-١٩ — النشر: Docker + CI (+ منصّة الاستضافة)

> **الحالة:** 🟡 قيد التنفيذ.
> **المتطلَّبات:** NFR-09 (`Dockerfile` وكل إعداد من متغيّر بيئة، الوجهة
> مؤجَّلة — ف-٥) — **هذه الوحدة هي "الوحدة الأخيرة" التي يحسم فيها ف-٥
> نفسه.** CI **ليست** في `SCOPE.md` الأصليّ — توسيعٌ صريح من المستخدم.
> **لماذا:** لا Docker ولا CI ولا نشرٌ فعليّ حتى اليوم رغم اكتمال ٢٥/٢٥
> شاشة و٤٤/٤٥ متطلَّبًا خلفيًّا.

---

## الفرز

مختلفة الطبيعة عن كل شرائح `ui/` السابقة: لا شاشة ولا عقد API، **بنية
تحتية بحتة**. تُقسَّم لثلاث مراحل مستقلّة القيمة (كلٌّ ينفع بلا التالي):

**أ. تحقّق محليّ** — `docker compose up` يشغّل كامل المكدَّس (قاعدة + تطبيق
مبنيّ) على هذا الجهاز، بلا منصّة سحابية. **طُلب أوّلًا صراحةً** — "تجربة
على لوكال هوست" قبل أي قرار استضافة.

**ب. اختيار المنصّة** — بحثٌ حيّ (لا افتراضٌ من الذاكرة، الأسعار/الحدود
المجانية تتغيّر) عن منصّة مجانية أو رخيصة وسهلة، بعد تجربة فاشلة سابقة مع
Render (انتهت حصّته المجانية).

**ج. CI** — اختبارٌ آليّ عند كل دفعة. **بلا `push` فعليّ** — لا remote
للمستودع، فالملفّات تُكتب جاهزة لا تُختبَر حيًّا حتى يُربَط المستودع بمنصّة
استضافة كود (قرار المستخدم الصريح).

## ١. Recon — المرحلة أ (التحقّق المحليّ)

### ١.١ ما هو مقرَّر سلفًا في التوثيق — لا يُخترَع هنا

- **`ARCHITECTURE.md` §٨:** `Dockerfile` **واحد** · كل إعداد من البيئة ·
  **لا هجرة تلقائية عند الإقلاع** (Alembic يدويًّا) · `GET /health` يفحص
  اتصال القاعدة فعلًا (**مبنيّ سلفًا** — `app/__init__.py:51`) · سجلّات
  نصّية لـ`stdout` (لا إعداد إضافي، `gunicorn` يفعل هذا افتراضًا).
- **`vite.config.ts`'s تعليقٌ صريح من و-١٣ نفسه:** *"في الإنتاج تكون
  الواجهة والـAPI على أصل واحد"* — **يحسم معنى "Dockerfile واحد" فعليًّا**:
  Flask يخدم بناء `ui/` الساكن مباشرةً (لا Nginx ولا حاوية ثانية)، فيبقى
  أصلًا واحدًا كالتطوير (وكيل Vite يحاكي هذا محليًّا) بلا حاجة لـCORS في
  الإنتاج إطلاقًا.
- **`gunicorn` مُدرَجة أصلًا في `requirements.txt`** («خادم الإنتاج — خادم
  فلاسك التطويري غير آمن له») بلا استهلاك حتى الآن — نفس نمط الدروس
  ٣١/٣٢/٣٣ (بنية تُثبَت باستهلاكها لا ببنائها)، تُستهلَك هنا لأوّل مرّة.
- **`.env.example`** يعدّد كل متغيّرات البيئة المطلوبة فعلًا
  (`DATABASE_URL`, `SECRET_KEY`, `SESSION_COOKIE_SECURE`,
  `CORS_ALLOWED_ORIGINS`, `FLASK_APP`, `EXPOSE_API_DOCS`) — **قائمة
  موجودة سلفًا لا تُخمَّن**.
- **لا مسار Flask يخدم ملفًّا ساكنًا اليوم** (`app/__init__.py` يسجّل ثلاثة
  Blueprints فقط) — إضافة الخدمة الساكنة + رجوع SPA (أيّ مسار غير مطابَق
  يُعاد له `index.html`، ضروريّ لتصفّح History API — ADR-008 — عند تحديث
  صفحة أو رابط عميق) **تغييرٌ حقيقيّ في كود `api/`**، أوّل مسّ له منذ بدء
  شرائح `ui/`.

### ١.٢ ما هو منفصل عمدًا عن هذا — `api/docker-compose.yml` القائم

الملفّ الحاليّ (قاعدة تطوير وحدها، `asrab-v2-db`) **يبقى كما هو** — يخدم
تدفّق التطوير اليوميّ (`flask run` + `vite` منفصلَين) الذي لا تُغيّره هذه
الشريحة. الجديد هنا ملفّ **مختلف الغرض**: تشغيل المكدَّس **المبنيّ** (صورة
Docker حقيقية) على قاعدة بيانات **منفصلة** — لا تُخلَط بيانات التجربة
الإنتاجية ببيانات التطوير اليوميّة.

## ٢. Reconcile — المرحلة أ

| # | القرار |
|---|---|
| ١ | `Dockerfile` واحد **متعدّد المراحل**: مرحلة `node` تبني `ui/` (`npm ci && npm run build` → `dist/`)، ثمّ مرحلة `python` تُثبِّت `requirements.txt` وتنسخ `api/` + `ui/dist/` الناتجة — يبقى "ملفًّا واحدًا" حرفيًّا رغم مرحلتين، ويطابق NFR-09 |
| ٢ | `app/__init__.py` يكتسب خدمة ساكنة لـ`ui/dist/` + رجوعًا لـ`index.html` لأي مسار غير API غير مطابَق — **تغييرٌ حقيقيّ وحيد في كود `api/`** هذه الشريحة، مبرَّرٌ بمتطلَّب نشر لا تعسّفًا |
| ٣ | `gunicorn "app:create_app()"` — نمط المصنع المباشر (مدعوم منذ gunicorn ٢٠)، لا حاجة لملفّ `wsgi.py` جديد |
| ٤ | الهجرات **يدويّة صراحةً بعد الإقلاع** — أمرٌ منفصل موثَّق (`docker compose run --rm app flask db upgrade`)، لا `ENTRYPOINT` يشغّلها تلقائيًّا (يخالف `ARCHITECTURE.md` §٨ حرفيًّا لو فُعل) |
| ٥ | `docker-compose.yml` **جديد في جذر المستودع** (لا داخل `api/`) — يُرتّب المكدَّس كاملًا (`db` + `app`)، بقاعدة بيانات وحجمٍ ومنفذٍ **منفصلين** عن `asrab-v2-db` التطويريّ |
| ٦ | `.dockerignore` جديد يستبعد `node_modules/`، `.venv/`، `dist/` المحليّ، `.git/` — سياق بناء أصغر وأسرع |
| ٧ | `PORT` (لا `5055` مثبَّتًا) — أغلب منصّات الاستضافة تُملي المنفذ عبر متغيّر بيئة؛ `gunicorn --bind 0.0.0.0:$PORT` يتوافق مع أيّ منصّة تُختار في المرحلة ب بلا تعديل لاحق |
