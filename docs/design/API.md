# واجهة الـAPI (Stage 3)

> **القاعدة:** كل endpoint يقابل متطلَّبًا، وكل متطلَّب له endpoint. الفجوات تُعلَن.
> **التوليد:** `flask-smorest` يولّد OpenAPI من `schemas/` — **العقد من الكود لا
> بجانبه**، فلا يفترقان بعد شهر.

---

## ١. قواعد عامّة

| | |
|---|---|
| الجذر | `/api` |
| الترميز | JSON · UTF-8 |
| المصادقة | كوكي جلسة `HttpOnly` — **لا ترويسة `Authorization`** |
| التواريخ | ISO-8601 بـUTC في النقل · **العرض بتوقيت المنظمة في الواجهة** |
| الأرقام | نصّ عشري للمبالغ (`"12.50"`) — **لا `float`** فلا يفقد الدقّة في JS |
| الترقيم | `?limit&cursor` حيث تكبر القائمة |

**كل طلب غير `GET`/`HEAD`** يمرّ بفحص `Origin` — **وغيابها رفضٌ لا تساهل**
(`403`). طبقة ثانية فوق `SameSite=Lax` (ADR-006).

**حدود المعدّل:** `/auth/login` ٥/١٥د · `/notes` ١٠/ساعة · `/me/readings` ٢٠/يوم.
تجاوزها `429` **يذكر متى يُفتح**.

**كل ردّ خطأ بالشكل نفسه:**
```json
{ "message": "الرسالة التي يقرأها المستخدم", "errors": { "field": ["..."] } }
```
**حتى غير المتوقَّع منه:** معالج في `create_app` يلتقط أي استثناء غير ملتقَط،
**يسجّل التفصيل ولا يرسله**، ويردّ `500` بنفس الشكل. بلاه يردّ Flask صفحة HTML
فيكسر العقد، ويعرض أثر التنفيذ في وضع التنقيح.

### الحرّاس
| الحارس | يفرض |
|---|---|
| `@login_required` | جلسة سارية غير مُبطَلة |
| `@admin_required` | العضوية الحالية `role='admin'` |
| **نطاق كل استعلام إداري** | **`org_id` وحده.** المشرف على مستوى الجمعية — `team_id` مرشّح واجهة **لا حاجز أمني** (`ARCHITECTURE.md` §٧.٣) |

## ٢. مسارات بنيوية — بلا متطلَّب وظيفي

| المسار | الطريقة | الغرض البنيوي | الحارس |
|---|---|---|---|
| `/health` | GET | **يفحص اتّصال القاعدة فعلًا** لا يردّ `200` أعمى | — |
| `/openapi.json` · `/docs` | GET | العقد المولَّد من `schemas/` | **معطَّل افتراضيًّا** — يُفعَّل بـ`EXPOSE_API_DOCS` |

**لماذا لا متطلَّب لها؟** لأنها تخدم **التشغيل لا المستخدم**: منصّة الاستضافة
تحتاج نقطة فحص، والمطوّر يحتاج العقد. **وهذا استثناء معلَن لا فجوة تتبّع** —
البوابة تشترط «متطلَّب **أو** غرض بنيوي موثَّق».

> `/health` يفحص القاعدة لأن خادمًا يردّ `200` وقاعدته ساقطة **يخدع المراقبة
> ويؤخّر اكتشاف العطل**.

## ٣. المصادقة

| المسار | الطريقة | الغرض | FR | الحارس |
|---|---|---|---|---|
| `/auth/login` | POST | دخول بـ`student_no` + PIN · قفل بعد ٥ محاولات | FR-001 · FR-003 | — |
| `/auth/logout` | POST | إبطال الجلسة **في القاعدة** | FR-002 | `login` |
| `/auth/me` | GET | المستخدم الحالي ودوره | FR-002 | `login` |

**`POST /auth/login`**
```json
→ { "student_no": "1042", "pin": "8317" }
← 200 { "user": { "id": 7, "full_name": "...", "role": "pilot" } }
```
| خطأ | الرمز | الرسالة |
|---|--:|---|
| بيانات خاطئة | 401 | **«رقم الطالب أو الرمز غير صحيح»** — رسالة **واحدة** للحالتين |
| حقل مجهول (مثل `org_id`) | 422 | يُرفض صاخبًا لا يُتجاهل صامتًا |
| قفل | 429 | «حاولت ٥ مرات. جرّب بعد ١٥ دقيقة.» — **يذكر متى** |

> 🔒 التفريق بين «رقم غير موجود» و«رمز خاطئ» يحوّل الشاشة إلى **أداة تعداد
> للطلاب**. الرسالة الواحدة ليست غموضًا بل ضمانة.
>
> **والزمن جزء من الرسالة.** بلا تهشير وهمي حين لا يوجد المستخدم، يردّ الرقم
> المجهول فورًا ويدفع الموجودُ كلفة argon2id — فارقٌ **مقيسٌ ٨.٩×** يعيد التعداد
> من باب آخر. `services/auth._DUMMY_HASH` يغلقه، و
> `test_unknown_student_costs_the_same_time_as_wrong_pin` يحرسه.

## ٤. الطيار

| المسار | الطريقة | الغرض | FR |
|---|---|---|---|
| `/me/deck` | GET | البطاقة: رتبة · ساعات · تقدّم · حالة | FR-010 · FR-011 · FR-013 |
| `/me/events` | GET | سجلّ الأحداث شاملًا التصحيحات | FR-012 |
| `/me/readings` | GET | طلبات قراءتي وحالاتها | FR-024 |
| `/me/readings` | POST | إرسال طلب قراءة | FR-020 · FR-021 |

**`GET /me/deck`** — **كل رقم محسوب في الخادم** (NFR: الواجهة تعرض ولا تحسب):
```json
{
  "rank":       { "name": "طيار أول", "tier": 2 },
  "hours":      "612.25",
  "next_rank":  { "name": "رائد سرب", "at_hours": "900.00",
                  "progress_pct": 42.5, "remaining": "287.75" },
  "flight":     { "grounded": false, "last_activity_on": "2026-08-28" },
  "team":       { "name": "سرب الفرقان", "rank_in_org": null }
}
```
- **الرتبة التالية بالنسبة إلى الرتبة لا إلى الساعات.** رصيدٌ سالب بعد تصحيح
  يبقي صاحبه في أدنى رتبة وتاليتُه الثانية — ولو قيست بالساعات لأعادت العتبة
  نفسها فتصير الشريحة صفرًا (قسمة على صفر، أُصلحت في و-١).
- `progress_pct` **داخل الشريحة**: ٦١٢ ساعة نحو «رائد سرب» = **٤٢.٥٪ لا ٦٨٪**
  (ط-٣). الفرق بين الشريحة والمطلق هو أشيع خطأ في شرائط التقدّم.
- في أعلى رتبة: `next_rank: null` ← الواجهة تعرض **رسالة إتمام لا شريطًا ممتلئًا**.
- طالب بلا أحداث: `hours: "0.00"` و`rank.tier: 1` — **حالة مصمَّمة لا مكسورة**.
- طالب بلا عضوية سارية: `team: null` — منقولٌ بين الأسراب يرى بطاقته لا شاشة عطل.

> **`team.rank_in_org` قابل للعدم — وهذا عقدٌ معلَن لا سهو.**
>
> الحقل **ترتيب السرب بالمعدّل**، وهو FR-051 يملكه `services/standings` في
> الوحدة ٩ (`TRACEABILITY.md`). و`/me/deck` يُبنى في الوحدة ١، فيردّ `null`
> حتى ذلك الحين.
>
> **`null` تعني «غير محسوب بعد» لا «لا سرب له».** غياب السرب نفسه يُمثَّل
> بـ`team: null`.
>
> **ولا يُحسب الترتيب داخل `deck` كحلٍّ مؤقّت:** نسخة ثانية من قاعدة الترتيب
> ستفترق عن `standings` عند أوّل تعديل في فكّ التعادل (FR-052)، فيرى الطالب
> رقمين مختلفين لسربه في شاشتين. **الحقل الفارغ أصدق من الرقم المكرَّر.**

**`POST /me/readings`**
```json
→ { "read_on": "2026-08-29", "pages": 40, "book_title": "..." }
← 201 { "id": 88, "status": "pending" }
```
| خطأ | الرمز |
|---|--:|
| طلب مكرّر لنفس اليوم والكتاب | 409 |
| `pages ≤ 0` أو تاريخ مستقبلي | 422 |

**لا ساعات في الردّ** — الطلب لا يمنح شيئًا قبل الاعتماد (FR-021).

**`read_on`** يُحوَّل إلى `occurred_at` **عند الاعتماد** بقاعدة `RULES.md` §٩:
بداية اليوم بتوقيت المنظمة إلى UTC. والتاريخ المستقبلي يُقاس **بتوقيت المنظمة**
لا UTC — وإلا رُفضت قراءةُ مساءِ الخميس في الرياض لأن UTC ما زال في الأربعاء.

**`GET /me/events`** — سجلّ ساعات **الطالب المصادَق عليه**، الأحدث أوّلًا:
```json
{
  "events": [
    { "id": 91, "kind": "reading",    "delta": "6.00",
      "occurred_on": "2026-08-29", "reason": null },
    { "id": 88, "kind": "quran",      "delta": "611.25",
      "occurred_on": "2026-08-28", "reason": null },
    { "id": 84, "kind": "correction", "delta": "-40.00",
      "occurred_on": "2026-08-20", "reason": "خطأ في تصدير راصد" }
  ]
}
```
- `delta` **نصّ عشري** كبقية المبالغ · **والسالب يظهر بإشارته** لا بقيمته المطلقة.
- `reason` **غير فارغ في التصحيحات** (`kind='correction'`) — وهو ما يوجبه ث-٧.
- `occurred_on` **تاريخ وقوع الحدث لا تسجيله**، بتوقيت المنظمة (`RULES.md` §٩).
- **لا معرّف مستخدم في الطلب ولا في المسار:** الهوية من الجلسة.
- قائمة فارغة ⇒ `{"events": []}` بـ`200` — **حالة مصمَّمة لا خطأ**.
- الترقيم `?limit` (افتراضيًّا ٢٠، بحدّ أعلى ١٠٠).

> 🔒 **التصحيحات لا تُخفى** (ط-٤): «إخفاؤها هو ما يثير الشك لا إظهارها». طالبٌ
> يرى رصيده نقص بلا سطر يفسّره يظنّ خللًا أو تلاعبًا — والسطر بسببه يُنهي الشكّ.

**`GET /me/readings`** — طلبات **الطالب المصادَق عليه** وحده، الأحدث أوّلًا:
```json
{
  "readings": [
    { "id": 91, "read_on": "2026-08-30", "pages": 25, "book_title": "…",
      "status": "pending",  "review_reason": null, "reviewed_at": null,
      "hours": null },
    { "id": 88, "read_on": "2026-08-29", "pages": 40, "book_title": "…",
      "status": "approved", "review_reason": null,
      "reviewed_at": "2026-08-31T06:12:00Z", "hours": "6.00" },
    { "id": 84, "read_on": "2026-08-27", "pages": 12, "book_title": "…",
      "status": "rejected", "review_reason": "الكتاب خارج القائمة المعتمدة",
      "reviewed_at": "2026-08-28T09:40:00Z", "hours": null }
  ]
}
```
- `status ∈ ('pending','approved','rejected')`.
- **`review_reason` غير فارغ في `rejected` حصرًا** (ث-٦) — والطالب يراه: رفضٌ
  صامت يقتل الثقة أسرع من غياب الميزة (FR-024).
- **`hours` غير فارغ في `approved` حصرًا** (ث-٥)، ونصّ عشري كبقية المبالغ.
  ويأتي **محسوبًا من الحدث** لا من `pages × وزن` في الواجهة (AGENTS ٥).
- **لا معرّف مستخدم في الطلب ولا في المسار:** الهوية من الجلسة، فلا يوجد ما
  يُتلاعب به — وهذا أقوى من التحقّق من الملكية لأنه يُلغي المسار المحتاج إليه.
- قائمة فارغة ⇒ `{"readings": []}` بـ`200` — **حالة مصمَّمة لا خطأ**.

**`GET /boards/teams`** — بالمعدّل لا بالمجموع، **وإلا صار الترتيب قياسًا للحجم**:
```json
[ { "team": "سرب الفرقان", "avg_hours": "412.30", "members": 6,
    "readiness": { "flying": 5, "grounded": 1 } } ]
```
`readiness` **عدّاد مجمّع بلا أسماء** — إشارة لوحة الجاهزية المحذوفة كصفحة.
**استعلام واحد بلا N+1** (ط-٧). **وفكّ التعادل بمعيار ثابت معلَن في الواجهة.**

**`GET /boards/formation`** — محكوم بـ**ف-١**:
```json
{ "scope": "team",
  "aircraft": [ { "name": "...", "size": 412.3, "grounded": false } ] }
```
| النطاق | يُعرض |
|---|---|
| داخل السرب | **الأسماء كاملة** شاملة الساقطين |
| الصدارة العامّة | **إنجاز فقط** — لا اسم لساقط |

**`POST /questions/{id}/answer`**
```json
→ { "choice_id": 2 }
← 200 { "correct": false, "correct_id": 3, "note": "الشرح...",
        "awarded_hours": "0.00" }
```
- **الجواب الصحيح وشرحه يظهران في الحالتين** — الخطأ فرصة تعلّم لا عقوبة (ط-٦).
- إجابة ثانية → **409** بقيد `UNIQUE` في القاعدة، **لا بإخفاء الزر**.
- «اليوم» **بتوقيت المنظمة لا المتصفّح**.

**`POST /notes`** → `201` بجسم فارغ. **لا `id` يُعاد** — معرّف يعود للمرسِل يخلق
خيط ربط حيث وعدنا ألّا يكون. الجهالة **بنية الجدول** (§٣ في `DATABASE.md`).

**`GET /station`** — محطة التزوّد (FR-072). **قرار مؤرَّخ (و-٨):** رغم أنها
تحت `POST /admin/fuel/assess` في `TRACEABILITY.md`، هي شاشة **طيّار** لا مشرف —
`@login_required` لا `@admin_required` — لأن م-٧ عن *تقييم* المشرف، أمّا *عرض*
الوقود فحقّ كل عضو في سربه (تناظر `/boards/*` و`/questions/*` في هذا القسم
تمامًا لا §٦). الهوية والسرب من الجلسة — لا معرّف سرب في الطلب:
```json
← 200 {
  "team": { "name": "سرب الفرقان", "litres": "340.00" },
  "tank_capacity_l": "500.00",
  "recent": [
    { "activity_name": "الحفظ الجماعي", "occurred_on": "2026-08-20",
      "total_pct": "93.50", "litres": "46.75" }
  ]
}
```
- `team: null` إن كان الطيار بلا عضوية سارية — **حالة مصمَّمة لا مكسورة**
  (`SCOPE.md` ط-٢)، بنفس عقد `team: null` في `GET /me/deck`.
- `litres` **تراكميّ** لا نافذة — `SUM(delta) WHERE scope='team'` للسرب.
- `recent` آخر ١٠ تقييمات (الأحدث أوّلًا) — **تفصيل يشرح الرقم** (FR-071)، لا
  مجموع صامت.

## ٦. المشرف

### اللصق والقرآن
| المسار | الطريقة | الغرض | FR |
|---|---|---|---|
| `/admin/paste/preview` | POST | **معاينة بلا كتابة** | FR-030 · FR-031 · FR-032 |
| `/admin/paste/commit` | POST | تنفيذ بعد المعاينة | FR-033 · FR-034 |
| `/admin/quran/entry` | POST | إضافة سجلّ ناقص يدويًّا | FR-036 |
| `/admin/events/{id}/reverse` | POST | تصحيح بحدث معاكس | FR-035 · FR-080 |

**`POST /admin/paste/preview`** — **لا يكتب شيئًا**:
```json
→ { "text": "الاسم\tحفظ\tمراجعة\tحضور\n..." }
← 200 {
  "batch_token": "…",
  "matched":   [ { "row": 1, "user_id": 7, "activities": {...} } ],
  "ambiguous": [ { "row": 2, "raw_name": "عبدالله السالم",
                   "candidates": [ {"user_id": 12, "score": 0.91} ] } ],
  "rejected":  [ { "row": 5, "reason": "لا مطابقة للاسم «...»" } ],
  "duplicates": 3
}
```
| القرار | لماذا |
|---|---|
| **مرحلتان (معاينة ← تنفيذ)** | الكتابة المباشرة تعني اكتشاف الخطأ بعد وقوعه |
| `ambiguous` **لا تُطبَّق تلقائيًّا** | مطابقة قريبة تنسب ساعات لطالب خطأ ولا يكتشفها أحد |
| `duplicates` معروض | يشرح للمشرف **لماذا** لم تُضَف صفوف — بلا شرح يظنّ أن النظام فشل |
| **الترويسة إلزامية** | عمودان متبادلان بصمت = أرقام معقولة الشكل خاطئة تمامًا |
| الحضور **عمود اختياري** | ف-١٠ — إن غاب فلا شيء يُكسر |

**`POST /admin/paste/commit`** — معاملة واحدة · idempotent بـ`external_ref` ·
**إعادة اللصق لا تضاعف** (اختبار إلزامي، م-١).

**`POST /admin/events/{id}/reverse`**
```json
→ { "reason": "خطأ في تصدير راصد — صفحات مضاعفة" }
← 201 { "id": 5012, "delta": "-40.00", "kind": "correction" }
```
> `reason` **إلزامي**. `422` بدونه. تصحيحٌ بلا سبب يبدو تلاعبًا في بطاقة الطالب.
> و**لا `UPDATE` ولا `DELETE`** — هذا هو ما يجعل مرونة التعديل الكاملة ممكنة
> بلا فقدان التاريخ.

> **`fuel_activities`/`fuel_criteria` بلا قصّة FR مستقلّة** — م-٧ يفترض
> وجودهما. `POST /admin/fuel/activities` **بنية تحتية ضرورية لتشغيل FR-070
> فعليًّا** (قرار مؤرَّخ، و-٨) — بلا مسارٍ لإنشاء نشاط، «أقيّم نشاطًا» جملة
> بلا مرجع. تُبنى **بأقلّ سطح ممكن**: إنشاء يجمع النشاط وبنوده في طلب واحد،
> نفس نمط تجميع `weights`+`multipliers` في `POST /admin/weights`.

**`GET /admin/fuel/activities`** — الأنشطة غير المؤرشَفة وبنودها:
```json
← 200 { "activities": [
  { "id": 1, "key": "group_memorize", "name": "الحفظ الجماعي", "litres_full": "50.00",
    "criteria": [ { "id": 1, "key": "attendance", "name": "الحضور", "weight_pct": "40.00" },
                  { "id": 2, "key": "quality", "name": "الجودة", "weight_pct": "60.00" } ] }
] }
```

**`POST /admin/fuel/activities`** — إنشاءٌ **جديد** لا تعديل على نشاط قائم:
```json
→ { "key": "group_memorize", "name": "الحفظ الجماعي", "litres_full": "50",
    "criteria": [ { "key": "attendance", "name": "الحضور", "weight_pct": "40" },
                  { "key": "quality", "name": "الجودة", "weight_pct": "60" } ] }
← 201 { "id": 1 }
```
`422` إن كان مجموع `weight_pct` ≠ ١٠٠ بالضبط — **ث-١٠أ**، في الخدمة والقاعدة معًا.

**`POST /admin/fuel/assess`** — تقييمٌ **جديد**، لا تعديل على تقييم قائم.
`team_id` صريح في الجسم — **المشرف على مستوى الجمعية** يقيّم أيّ سرب (§٧.٣)،
لا سربه وحده:
```json
→ { "team_id": 1, "activity_id": 1, "occurred_on": "2026-08-20",
    "scores": [ { "criterion_id": 1, "score_pct": "100" },
                { "criterion_id": 2, "score_pct": "90" } ],
    "note": "ملاحظة اختيارية" }
← 201 { "id": 12, "total_pct": "94.00", "litres": "47.00" }
```
| الرفض | لماذا |
|---|---|
| `422` — مجموع `weight_pct` **للبنود المُرسَلة فعلًا** ≠ ١٠٠ | **ث-١٠ب**: انجراف بين تعريف النشاط ولحظة التقييم — نشاطٌ سليم عند الإنشاء قد يُفسَد لاحقًا |
| `422` — بندٌ لا ينتمي لهذا النشاط | تقييم بند نشاط آخر بالخطأ |
| `409` — نفس السرب ونفس النشاط ونفس `occurred_on` مقيَّمان من قبل | `uq_fuel_assessment_per_day` |

**الأوزان تجمع ١٠٠٪ بالضبط** — حرسًا مزدوجًا (ث-١٠أ عند تعريف البنود ·
ث-١٠ب عند التقييم لا مرحلة واحدة): نشاطٌ أوزانه ٩٥ يجعل الإتقان الكامل ٩٥٪،
**فيظنّ السرب أنه قصّر وهو أتقن**.

`total_pct = Σ(score_pct × weight_pct) / 100` · `litres = total_pct/100 × litres_full`.
**الدرجات تُحفظ مفصّلة** (`fuel_scores`) ليُشرح الرقم لاحقًا (FR-071) ·
`occurred_on` **تاريخ الوقوع لا الإدخال** يُحوَّل إلى UTC بتوقيت المنظمة
(`RULES.md` §٩) · **يُسجَّل في `audit_log`** بـ`kind='fuel_assessment'`.

**`GET /admin/weights`** — الإصدار الأحدث والسُّلّم الكامل خلفه:
```json
← 200 {
  "current": {
    "id": 3, "effective_from": "2026-09-01T00:00:00Z", "note": "معايرة سبتمبر",
    "weights": [ { "activity_type": "memorize", "hours_per_unit": "2.5000" } ],
    "multipliers": [ { "grade": "mastered", "multiplier": "1.500" } ]
  },
  "history": [ { "id": 2, "effective_from": "2020-01-01T00:00:00Z", "note": "…" } ]
}
```

**`POST /admin/weights`** — إصدارٌ **جديد**، لا تعديل على القائم (ث-١١):
```json
→ {
  "effective_from": "2026-09-15",
  "note": "معايرة بعد شهر بيانات حقيقية",
  "weights": [ { "activity_type": "memorize", "hours_per_unit": "2.8" } ],
  "multipliers": [ { "grade": "mastered", "multiplier": "1.5" } ]
}
← 201 { "id": 4, "effective_from": "2026-09-15T00:00:00Z" }
```
| الرفض | لماذا |
|---|---|
| `422` — `effective_from` **لا يأتي بعد** آخر إصدار قائم | إصدارٌ يسبق آخر إصدار يُلبِس `ruleset_at` أيّهما ساري وقت أيّ لحظة |
| `422` — نشاطٌ كان له وزن في الإصدار السابق وغاب من هذا | نشاطٌ يصير **مستحيل الاحتساب** فجأة — `hours_for` سترفعه لاحقًا **في وجه طالب لا مشرف** |
| `403` غير مشرف · `401` بلا كوكي | كالمعتاد |

`effective_from` **تاريخ محلّي** يُحوَّل إلى بداية اليوم بتوقيت المنظمة ثم UTC
(`RULES.md` §٩) — نفس تحويل `reading.occurred_at_for`، لا آلية موازية.

**يُسجَّل في `audit_log`** بـ`kind='weights_version'` منسوبًا للمشرف،
`after` يحمل معرّف الإصدار وتاريخ سريانه — **بلا نسخ كل الأوزان** (`before`/`after`
ملخّص لا نسخة كاملة، فرقٌ متعمَّد عن `pin_reset` الفارغَين تمامًا).

**`GET /admin/thresholds`** — السُّلّم الحالي مرتّبًا بـ`tier`:
```json
← 200 { "thresholds": [
  { "key": "trainee", "name": "طيار", "tier": 1, "at_hours": "0.00" },
  { "key": "pilot1", "name": "طيار أول", "tier": 2, "at_hours": "400.00" }
] }
```

**`POST /admin/thresholds/preview`** — من يرتفع ومن ينخفض **قبل** الحفظ، بلا
كتابة:
```json
→ { "thresholds": [ { "key": "trainee", "name": "طيار", "tier": 1, "at_hours": "0" },
                     { "key": "pilot1", "name": "طيار أول", "tier": 2, "at_hours": "500" } ] }
← 200 { "promoted": [ {"user_id": 3, "from_tier": 1, "to_tier": 2} ],
        "demoted": [], "warning": null }
```
**والرتبة المعروضة لا تنخفض** (و-٧ · ت-٢): `demoted` يبقى فارغًا **دائمًا**، لأن
كل طالب يُعرَض له `max(الرتبة المحسوبة تحت السُّلّم الجديد, users.highest_achieved_tier)`
— لا لأن الحساب يُخفي حقيقة، بل لأن العتبة المرتفعة **لا تسحب رتبة بلغها فعلًا**
تحت عتبة أقدم. التفصيل الكامل: `docs/slices/و-٧.md` §الرتب لا تنخفض.

| الرفض | لماذا |
|---|---|
| `422` — سُلّم يخالف **ث-١٣أ** (`tier` أعلى ⇔ `at_hours` أعلى) | نفس الفحص في المعاينة والحفظ — معاينة تقبل ما يرفضه الحفظ تكذب على المشرف |
| `422` — مفتاح `key` قائم غائبٌ عن الإرسال | حذف رتبة يتيّم كل من بلغها — لا حذف، إضافة فقط |

**`POST /admin/thresholds`** — نفس جسم `preview`، **يحفظ** ويُرجع نفس شكل
`preview`، ثم يُسجَّل في `audit_log` بـ`kind='thresholds_update'`، `before`/`after`
السُّلّمان كاملين (صغيران بحكم التعريف — أربعة إلى عشرة صفوف).

**`GET /admin/report`** — ملخّص دوري **مشتقّ من سجلّ الأحداث بلا جدول جديد**:
```json
{
  "window": { "from": "2026-08-24", "to": "2026-08-31", "days": 7 },
  "totals": { "hours": "128.50", "active_pilots": 4, "grounded_pilots": 1 },
  "teams": [
    { "id": 1, "name": "سرب الفرقان", "hours": "128.50",
      "members": 4, "avg_hours": "32.13" }
  ],
  "top_movers": [
    { "user_id": 3, "full_name": "ماجد القحطاني", "hours": "90.00" }
  ],
  "grounded": [
    { "user_id": 4, "full_name": "فهد الدوسري", "last_activity_on": "2026-07-31" }
  ]
}
```
- **النافذة `?days`** (افتراضيًّا ٧، بحدّ أعلى ٩٠) — والتقرير يقيس **حركة النافذة**
  لا الرصيد التراكمي: «من تقدّم» سؤالٌ عن الأسبوع لا عن العمر.
- `avg_hours` **معدّل لا مجموع** — اتّساقًا مع صدارة الأسراب (FR-051): المجموع
  يقيس الحجم لا الاجتهاد.
- **`grounded` بالاسم — لأنه للمشرف وحده.** القرار ٥ يمنع عرض المتأخّر بالاسم
  **للطلاب**، وهذه شاشة إشراف: المشرف يحتاج أن يعرف من يلاحق.
- **بلا جدول جديد ولا كتابة** — استعلامات قراءة على `point_events` و`memberships`.

**`POST /admin/users/{id}/reset-pin`** — إعادة تعيين رمز طالب (FR-004):
```json
→ (بلا جسم)
← 200 { "student_no": "1042", "pin": "8317" }
```
- **الرمز يُعرض مرّة واحدة** ولا يُخزَّن نصًّا صريحًا أبدًا (`ARCHITECTURE.md` §٧.٥).
- **كل جلسات الطالب تُبطَل فورًا** — سبب إعادة التعيين غالبًا فقدان الجهاز،
  وترك جلساته حيّة يُبطل الغرض.
- **يُسجَّل في `audit_log`** بـ`kind='pin_reset'` منسوبًا إلى **المشرف**،
  و`before`/`after` **فارغان**: «بلا قيمة الـPIN».
- طالب غير موجود ⇒ `404` · غير مشرف ⇒ `403` · بلا كوكي ⇒ `401`.

**`GET /admin/teams`** — كل أسراب المنظمة، **بما فيها المؤرشَفة** (مُعلَّمة):
```json
← 200 { "teams": [
  { "id": 1, "name": "سرب الفرقان", "code": "FRQ",
    "archived_at": null, "active_members": 4 }
] }
```

**`POST /admin/teams`** → `{ "name": "سرب الفجر", "code": "FJR" }`
```json
← 201 { "id": 2, "name": "سرب الفجر", "code": "FJR" }
```
`code` مكرَّر في المنظمة نفسها ⇒ `409` (`uq_team_code`).

**`PATCH /admin/teams/{id}`** → `{ "archived": true }` — **أرشفة لا حذف** (م-١٠):
```json
← 200 { "id": 2, "archived_at": "2026-09-01T12:00:00Z" }
```
`422` إن كان للسرب أعضاء ساريّون — **يُنقَلون أوّلًا**: أرشفةٌ تترك طلّابًا بلا
سرب حيّ تكسر بطاقتهم وصدارة الأسراب معًا.

**`POST /admin/teams/{id}/members`** → `{ "user_id": 7 }` — نقل طالب (FR-083):
```json
← 200 { "user_id": 7, "team_id": 2, "role": "pilot" }
```
| الرفض | لماذا |
|---|---|
| `422` — السرب الهدف مؤرشَف | لا عضوية جديدة في سربٍ لم يعد قائمًا |
| `404` — الطالب غير موجود أو من منظمة أخرى | رسالة واحدة — نفس علّة `reset-pin` |

**العضوية القديمة تُغلَق (`left_at=الآن`) لا تُحذَف، والجديدة تُفتح** — **النقل
لا ينقل التاريخ** (م-١٠): أحداث الطالب في `point_events` تبقى منسوبة كما وقعت،
فلا يقفز سربه الجديد في الترتيب بحدث لم يصنعه أعضاؤه. والدور **يُحمَل معه** —
مشرفٌ يبقى مشرفًا بعد النقل، لأن صلاحيته على مستوى الجمعية لا السرب (§٧.٣).

**الثلاثة تُسجَّل في `audit_log`** بـ`kind` بالترتيب `team_created` ·
`team_archived` · `membership_transferred`.

**`GET /admin/audit`** — **مفتوح لكل المشرفين لا لمالك المنظمة وحده.** هذا هو
التعويض الكامل عن دمج الدورين (`SCOPE.md` §٣.٣): الحماية **كشف الاستعمال** لا
**منع الصلاحية**. سجلٌّ يراه واحد فقط لا يحمي من شيء.
```json
← 200 { "entries": [
  { "id": 41, "kind": "thresholds_update", "summary": "تحديث سُلّم الرتب",
    "actor_name": "بندر الشمري", "at": "2026-09-01T12:00:00Z" }
] }
```
**فارغة صراحةً لا خطأ:** منظمة بلا تغييرات بعد ترجع `{"entries": []}` بـ`200` —
**معيار قبول قائم بذاته** (FR-084)، لا سلوكًا مفترَضًا: شاشةٌ تعرض «لا تغييرات
بعد» لا رسالة عطل ولا لوحًا فارغًا صامتًا. `before`/`after` **لا يظهران هنا
عمدًا** — قائمة مسح لا محرّر: من يحتاج التفصيل يفتح السطر (خارج نطاق و-٧).

**`POST /admin/recalc`** → `{ "dry_run": true }` **افتراضيًّا**. الردّ يعرض
التسويات قبل تطبيقها، **ولا يُحذف شيء أبدًا** — تُصدَر أحداث تسوية.

> ### تصحيح مقصود — `FR-004` صار مسارًا مستقلًّا
>
> **كان:** «يُغطّى ضمن `PATCH /admin/teams` — لا يستحقّ مسارًا مستقلًّا».
> **صار:** `POST /admin/users/{id}/reset-pin`.
>
> | لماذا | |
> |---|---|
> | **أمنيًّا** | فعلٌ **يُبطل كل جلسات مستخدم** يجب أن يكون صريحًا في العقد، لا حقلًا مدفونًا في `PATCH` عامّ — فلا يُطلَق عرَضًا بتغيير لاحق في مسار الأسراب |
> | **حدود الوحدات** | مسارٌ مشترك بين `FR-004` (و-٢) و`FR-083` (و-٧) يخلق **تبعية متقاطعة**: تغييرٌ في مسار و-٧ يكسر متطلَّب و-٢ صامتًا. والاستقلال هو ما يجعل ترتيب الوحدات مرنًا |
>
> **وهذا تصحيح لا تناقض:** الحشر في `PATCH` كان اختصارًا في التصميم قبل أن
> يتّضح أن الفعل أمنيّ لا إداري.
